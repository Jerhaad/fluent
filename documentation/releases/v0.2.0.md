# Fluent v0.2.0

Fluent v0.2.0 makes scheduler-owned work practical from first setup through a
reviewed Merge Candidate. It supports Codex-only, Claude-only, and mixed Codex
and Claude coder profiles on macOS.

## What changed

- The first-use flow now detects enclosing agent sandboxes, validates provider
  readiness, and gives the user a host-side command when authentication or
  nested macOS sandboxing cannot work inside the invoking agent's sandbox.
- Fluent now adopts its marked bootstrap skill without taking ownership of
  unrelated skills or lock entries. Reinstalling the managed skill preserves a
  current installation. Bare skill refreshes no longer create a Claude Code
  root by default; a new installation names `codex` or `claude` together with
  `--project` or `--global`.
- Queued Work uses the configured coder profile, resumes the same Attempt after
  provider or Tester pauses, and reports the terminal queue state. Scheduler
  status also identifies the running Fluent build so an installed update cannot
  silently reuse an older coordinator.
- Writers now complete a host-generated matrix that maps approved plan steps,
  execution guidance, review findings, and verification evidence. Cheap
  candidate checks run before review, and failed checks return directly to a
  corrective Writer.
- Reviews bind passing inspection evidence to the exact candidate commit.
  Missing test evidence can use one explicitly approved host-side command and
  rerun only the Tests Reviewer instead of repeating the full lifecycle.
- Corrections preserve the candidate and completed work across review failures,
  final-Tester failures, uncertain reviews, provider outages, and retryable
  Learner failures. Failed Tester commands can be rechecked before Fluent spends
  another full review round.
- Landed commits seed baseline results for later Work Items, avoiding a new
  baseline run when the same commit becomes a Work Item.
- Claude readiness diagnostics now distinguish authentication failures,
  provider capacity limits, enclosing-sandbox restrictions, and stalled
  launches. Provider wait time is included in Attempt status.
- Release publication now builds, signs, and checksums separate Apple Silicon
  and Intel macOS binaries.

## Installation security notice

The public `skills` scanner labels the Fluent bootstrap `High Risk`. The shim
runs `curl -fsSL fluent.computer/install | sh` when the Fluent binary is
missing, then loads the version-matched full skill written by that binary. The
scanner treats the remote installer and the generated instruction handoff as a
code-execution and supply-chain risk.

Fluent v0.2.0 retains this bootstrap design. Review
[`skills/fluent/SKILL.md`](https://github.com/mrinalwadhwa/fluent/blob/v0.2.0/skills/fluent/SKILL.md)
and the contents served by
[`fluent.computer/install`](https://fluent.computer/install) before running the
installer. The release assets themselves are checked against their published
SHA-256 files before installation.

## Upgrade

If a scheduler is running, let its current Work finish and stop it before
installing the new binary:

```sh
fluent scheduler status
fluent scheduler stop
fluent update
fluent version
fluent scheduler run
```

The reported version should start with `fluent 0.2.0`.

An older scheduler may not have build-identity metadata. In that case, stop it
from the terminal or process supervisor that launched it before starting the
new scheduler.

Existing Work Items and Attempts retain their durable lifecycle state. When an
existing Attempt is paused, use the exact resume command shown by
`fluent status`; scheduler-owned Work should return through `fluent queue
resume` rather than starting a separate Attempt.

Fluent v0.2.0 supports local execution on macOS. Fargate execution is not part
of this release's readiness claim.
