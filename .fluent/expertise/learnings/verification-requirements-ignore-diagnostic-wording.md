name: verification-requirements-ignore-diagnostic-wording
description: Bind current verification obligations to approved requirements and native evidence rather than diagnostic lines or historical Task order
metadata:
  type: architecture
---

Fluent derives each verification requirement from its durable source. Reference
identities bind the Work Item, Attempt, approved row, reference occurrence, and
original reference text. Canonical commands bind configuration and position;
native defects retain their qualified identity. Explanatory messages, observed
identity lists, and their ordering cannot create additional obligations.

Keep satisfaction, cause, owner, next action, and proof bindings together in the
current assessment. A behavior with no verification marker still needs one
unresolved row. Verification adds only established unresolved candidate defects
to Writer completion; diagnostic requirements and accepted external proof retain
their own owners. Keep historical artifacts unchanged, and reassess the current candidate
before interpreting them as current work. A changed candidate awaiting its first
Tester needs the pending assessment too.

Test agreement through the actual Writer requirements consumer, generated
execution context, candidate gate, status, and admission path. Supplying an
assessment directly to a findings helper misses whether a production caller
loads it. Include a corrective Task with real historical inputs, candidates
before their first Tester, changed diagnostic wording/order, and unchanged
Writer history. Assert stable obligations and preserved historical bytes while
invalidated proof still leaves its requirement outstanding.
