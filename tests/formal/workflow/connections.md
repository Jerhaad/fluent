# Workflow connection inventory

The whole-workflow model is an abstraction. Each row declares the concrete state
and required checks; a declaration does not claim those checks have passed. The
integrated report credits a row only when its evidence uses `Check: model=SUITE/CASE; assumption=SUITE/CASE;
production=SUITE/CASE; control=SUITE/CASE`. Each named case must pass in a
candidate-bound suite; model, production, and control cases must be distinct.
A passing component model alone does not complete a connection. The
six scheduler models remain separate checks.

The first trace covers public intake, Attempt creation, cancellation, read-only snapshots, and refusal of a Task run while canceled. `project.py` checks those facts and their artifact digests. The integrated queue/cancellation trace also checks that a later independent Git commit leaves the queued and canceled Work records and queue unchanged; rehashed changed-Work and changed-queue controls must each fail projection. All listed cases must pass on the exact candidate before the report credits these connections. Physical confinement and released shared-service execution remain host-owned; unavailable or skipped prerequisites leave those connections unverified. Development model runs do not replace the required Java 21 integrated run.
